공공데이터포털 상세 페이지에 포함된 공식 Swagger의 endpoint/필드로 구현했다.
복지로 중앙 개발계정의 일일 요청 한도는 100회, 지자체는 1,000회다.

이 수치는 프로세스별 제한이므로 수동 실행을 반복하면 일일 한도가 소진될 수 있다.
API 오류는 빈 목록 성공으로 처리하지 않으며 키/전체 응답을 로그에 기록하지 않는다.

e나라도움 종합 API는 공고 없는 일반 보조사업을 포함한다. 공식 `pblanc_nm` 파라미터에
`%`를 주면 공고명이 있는 연결 행만 반환됨을 실측했다. 같은 공고가 여러 보조사업에
연결된 경우 원문 URL로 중복 제거한다. 이스케이프된 CDATA 구분자도 제거한다.
필터를 무시하는 응답(공고명/공고 URL 없음)은 실패로 처리하여 일반 사업을 공고로 등록하지 않는다.
전체 조회 72개 유효 배치/411.5초는 기존 `/api/ingest`의 300초보다 길다.
따라서 e나라도움은 공통 cron에서 제외하고 HTTP 명시 요청도 거절한다. 별도 서버 CLI로만 실행한다.

## 활성화

새 수집처는 기본 OFF. 활용신청 승인 및 dry-run 확인 후 해당 서버 환경설정을 켠다.
키는 Git/브라우저에 저장하지 않는다. 동일 키에 이용 승인을 받았다면 기존 DATA_GO_KR_KEY를 재사용할 수 있다.

| 코드 | 활성화 변수 (`true`) | 별도 키가 필요한 경우 |
| --- | --- | --- |
| bokji-central | INGEST_BOKJI_CENTRAL_ENABLED | BOKJI_CENTRAL_API_KEY |
| bokji-local | INGEST_BOKJI_LOCAL_ENABLED | BOKJI_LOCAL_API_KEY |
| enara | INGEST_ENARA_ENABLED | ENARA_API_KEY |
| culture | INGEST_CULTURE_ENABLED | 불필요 |

```sh
# 읽기 전용. 기본 최대 20건 정규화, 원문이나 키 출력 없음
npm run ingest:expanded -- --source=mois,culture --limit=20
npm run ingest:expanded -- --source=bokji-central,bokji-local,enara --limit=5

# 전체 페이지 검증, DB 변경 없음
npm run ingest:expanded -- --source=mois,culture --all

# 운영 반영 승인 후에만 실행. 모든 페이지를 저장하므로 --limit와 병용 금지
npm run ingest:expanded -- --source=mois,culture --all --apply
```

`--apply`는 기존 수집기만 실행하며 마감 공고 삭제 함수를 호출하지 않는다.
새 출처 ID는 고정 숫자를 발명하지 않고 기존 `ensure_source_by_code` RPC를 재사용한다.
RPC가 없다면 중단한다. 자동 migration/DDL 실행은 없다.
비활성화된 `sources.enabled=false` 신규 출처는 실행하지 않는다.
코드와 활성화 변수를 배포하면 기존 인증된 cron 수집 경로에서도 복지로/문화포털 활성 출처가 실행된다.
e나라도움은 활성화 변수만으로 자동 수집되지 않는다. 승인된 장시간 작업 환경에서 아래 명령을 사용한다.

```sh
# 실제 DB 쓰기. 장시간 작업 환경에서 실행한다.
INGEST_ENARA_ENABLED=true npm run ingest:expanded -- --source=enara --all --apply
```

위 환경변수 지정은 POSIX 셸 예시다. PowerShell은 `$env:INGEST_ENARA_ENABLED='true'`로 지정한다.
최초 수집 당시에는 일일 자동화를 만들지 않았다. 이후 자동화 설정은 다음 절을 따른다.

## 정기 수집 및 상세 보강 (2026-10-16 추가)

- `.github/workflows/expanded-sources.yml`: 매일 08:17 KST 예약, GitHub Actions 대기열에 따라 지연될 수 있다.
- e나라도움 전체 CLI 수집과 복지로 중앙/지자체 상세 보강을 서로 독립된 작업으로 실행한다. 각 작업 제한시간 60분.
- 기존 Vercel 06:00 KST 목록 cron과 07:00 온통청년 cron은 유지한다. e나라도움을 300초 HTTP 함수에 넣지 않는다.
- e나라도움만 원천 요청/본문 수신 timeout 45초, 금년 우선 조회를 사용한다. 복지로 등 다른 출처는 15초를 유지한다.
- 복지로 추가 상세 예산은 중앙 하루 최대 60건, 지자체 최대 400건. 기존 목록 cron의 기본 상세 8건과 목록 요청을 위한 여유를 남긴다.
- `ingest_daily_jobs`에 KST 날짜/출처별 실행권을 먼저 원자적으로 기록한다. 같은 날 중복/수동 재실행은 API 호출 없이 종료한다.
- 실패하거나 중간 종료되어도 그날 실행권은 재사용하지 않는다. 실패는 다음 날 다시 시도한다. 강제 종료 기록은 `running`으로 남으므로 Actions 실패/취소 상태도 함께 확인한다.
- 예외: 운영자가 원인을 수정한 뒤 `recover_enara=true`로 수동 실행하면 **실패 상태인 e나라도움만 당일 1회** 복구 가능하다. 이전 실패 기록을 summary에 보존한다. 성공/진행중/이미 복구한 작업 및 복지로는 우회 불가.
- 상세는 미수집 우선, 이전 시도가 오래된 순서로 처리한다. 24시간 내 시도는 제외한다. 목록 payload 변경 또는 상세 수집 후 30일 경과 시 갱신 대상에 포함한다.
- 상세 API 오류 발생 시 현재 최대 3건 배치 뒤 해당 출처를 멈춘다. 자동 retry 없이 다른 출처는 계속 처리한다.
- 전체 공고/사용자 데이터는 Actions 로그에 출력하지 않는다. 결과는 건수/소요시간만 남기며 공고 삭제를 실행하지 않는다.
- 실행권 테이블/RPC는 RLS 활성 + service_role 전용이다. anon/authenticated에는 조회/수정/실행 권한이 없다.
- GitHub `production-ingestion` 환경에 API/DB 키를 암호화 보관하며 배포 브랜치는 `master`만 허용한다. 코드/문서에는 값이 없다.
- workflow는 PR/push 이벤트로 실행하지 않는다. 수동 실행은 Actions의 `Daily expanded sources`에서 가능하지만 당일 실행권을 우회하지 않는다.
- 공공 API 키의 다른 수동 호출/다른 서비스 사용량까지 통제하는 전역 quota 시스템은 아니다. 기존 `ingest:expanded`를 반복 실행하여 별도 예산을 소진하지 말 것.
- GitHub 공개 저장소는 60일 동안 저장소 활동이 없으면 예약 workflow가 비활성화될 수 있다. 장기 무변경 운영에서는 Actions 활성 상태/실행 기록을 확인한다.

```sh
# DB 대기열 읽기 전용 확인. 외부 공공 API 호출/DB 저장 없음.
npm run ingest:scheduled -- --source=bokji-central
npm run ingest:scheduled -- --source=bokji-local

# 당일 실행권이 남아 있을 때만 실제 수집/보강. 일반 운영은 Actions가 실행한다.
npm run ingest:scheduled -- --source=enara --apply
npm run ingest:scheduled -- --source=bokji-central --apply
npm run ingest:scheduled -- --source=bokji-local --apply
```

필요 환경변수는 `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `DATA_GO_KR_KEY`다.
로컬에서는 기존 환경파일 디렉터리를 `AISUP_ENV_DIR`로 지정할 수 있다. 키 자체는 출력하지 않는다.
스케줄 중지는 Actions workflow 비활성화로 처리한다. `sources.enabled=false`도 해당 출처 작업을 차단한다.
테스트: 정책/중복실행/실패처리/권한/워크플로 회귀 테스트를 포함한다.
운영 실행권 중복 테스트는 트랜잭션 rollback으로 수행하여 실제 일일 실행권을 소진하지 않았다.
운영 migration 버전은 `20261016011800_scheduled_source_jobs.sql`이다. CLI 생성 후 원격 적용 도구가 기록한 실제 버전에 파일명을 정렬했다.
최초 클라우드 실행에서 중앙 상세 60/60건(약 19초), 지자체 상세 400/400건(약 55초)이 저장됐다.
누적 상세는 중앙 68/461건, 지자체 408/4,819건이며 나머지는 일일 예산에 따라 보강한다.
중앙 작업 재실행은 `ALREADY_CLAIMED_TODAY`로 외부 API 호출 없이 종료됐고, 운영 PC/앱 상세 및 API는 HTTP 200으로 보강 내용을 제공했다.

## 표시 및 안전 원칙

- 사업 시작/종료일을 신청 시작/마감일로 바꾸지 않는다.
- 복지로의 생애주기·가구유형만으로 구체적인 나이 제한을 만들지 않는다.
- 복지로 상세 지원대상은 기존 상세 갱신 예산 안에서 보강한다. 아직 상세가 없으면 나이/자격은 미확인이다.
- 중앙부처/수행기관의 주소만으로 전국 또는 특정 지역 자격을 확정하지 않는다.
- 문화포털은 원문 링크 색인만 제공하며 원문 전체와 첨부파일은 복제하지 않는다.
- 정부24의 지원내용·선정기준·신청방법·문의처는 이미 제공된 API 필드를 상세 칼럼에 저장한다.
- 새 출처는 `source_code`/`source_name` JOIN을 사용하는 기존 PC·앱 표시를 재사용한다.
- 본 작업은 사용자 조건, 추천 점수 및 Android 네이티브 알림 규칙을 변경하지 않는다.

## 이용자 피드백 반영

- 지역별 페이지 이동: 지역/검색/분야/지원목적/연령 조건을 유지한다. 과도한 링크 prefetch를 끄고 DB statement timeout만 1회 재시도한다.
- 사무실 검색: 입주기업, 창업보육, 활동공간, 공유공간 등 실제 공고 표현으로 함께 검색한다.
- 비영리·복지단체 및 주민모임·동아리 대상 메뉴, 복지/공익/교육/생활체육/공간 목적 필터를 PC와 `/app`에 공통 적용했다.
- 나이: 명시적 상·하한만 사용한다. 청년이라는 단어를 39세 제한으로 바꾸지 않는다. 미확인 제외를 선택할 수 있다.
- 단체 수혜자 나이, 우대·예외·복수 조건 및 `18~0세` 같은 잘못된 원천 범위는 미확인이다. 나이 일치는 전체 신청자격 충족을 의미하지 않는다.
- 모든 출처의 이름을 카드에 표시하고 앱의 상태/정렬 문구를 실제 선택값과 맞춘다.
- 평일/야간/주말 참여시간 필터는 미구현이다. 현재 API에 일관된 참여 시간 구조가 없어 임의 추정하지 않는다.
- 보탬e·개별 교육청·체육회 전체 수집은 미연결이다. 현재 연결 범위를 넘어 전국 모든 지원사업이 포함됐다고 주장하지 않는다.
